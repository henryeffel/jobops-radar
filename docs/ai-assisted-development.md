# AI 협업 개발

## AI를 사용한 작업

- 반복 코드와 문서 초안 작성
- 테스트 및 누락된 경계 조건 제안
- Migration 검토 보조
- 채용공고 요구사항의 구조화 후보 추출과 사용자 프로필 비교

## 사람이 결정한 항목

- 도메인 경계와 인증 범위
- Token claim, 비밀번호 정책, 감사 데이터 최소화
- 최종 코드 검토와 한계 수용 여부

## 판단 사례

Refresh token은 의도적으로 제외했습니다. 불완전한 세션 생명주기를 추가하기보다 검증 가능한 로그인 흐름을 완성하는 데 우선순위를 두었습니다.

채용공고 분석의 LLM 출력은 그대로 신뢰하지 않습니다. 서버는 JSON schema를 검증하고 공고·프로필 근거 문장이 실제 입력에 포함되는지 확인한 뒤 중요도 가중 점수를 계산합니다. provider timeout, 503, 잘못된 JSON 또는 근거 불일치에는 결정론적 분석으로 전환합니다.

## 검증 원칙

- AI가 작성한 변경 사항은 사람이 최종 검토합니다.
- 보안에 민감한 동작은 정상·실패 경로를 모두 테스트합니다.
- Prompt에 인증 정보나 비밀 키를 포함하지 않습니다.
- API 키는 `.env`에서만 읽고 source, prompt, 로그에 포함하지 않습니다.
- 모델 reasoning은 저장하거나 API 응답으로 노출하지 않습니다.
- 실제 이력서는 분석에 필요한 경우에만 provider에 전달하며 개인정보 처리·보존 정책은 공개 배포 전에 별도로 확정합니다.
- fallback 사용 여부를 응답에 표시해 사용자가 분석 방법과 한계를 알 수 있게 합니다.

LLM 구조화 응답 실패의 재현·분류·수정 절차는 [LLM 구조화 분석 오류 개선 기록](experiments/llm-structured-analysis-troubleshooting.md)에 유지합니다.
