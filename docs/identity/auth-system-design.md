# 내부 인증 시스템 설계

## 범위

이메일·비밀번호 회원가입, 로그인, 수명이 짧은 access token, 인증된 현재 사용자 조회, 세 가지 감사 이벤트를 구현합니다.

## 보안 결정

- 비밀번호는 Argon2로 해싱하며 API 응답이나 로그에 남기지 않습니다.
- 존재하지 않는 이메일과 잘못된 비밀번호에 동일한 로그인 실패 응답을 사용합니다.
- JWT 검증 시 algorithm을 제한하고 subject, 발급 시각, 만료 시각, access token 유형을 필수로 검사합니다.
- 사용자가 없거나 비활성 상태이면 token 자체가 유효해도 접근을 거부합니다.
- 감사 metadata에는 요청 본문, 인증 정보, token을 저장하지 않습니다.

## 신뢰 경계

API는 설정된 하나의 비밀 키로 서명한 내부 bearer token을 발급합니다. TLS, 비밀 키 저장소, rate limiting, 키 교체, 중앙 관측 시스템은 배포 환경의 책임이며 현재 로컬 프로젝트에서 검증하지 않았습니다.

## 비목표

Refresh token, 로그아웃·폐기, 비밀번호 재설정, MFA, OIDC/OAuth Provider, 조직 멤버십, 운영용 세션 저장소는 현재 범위에 포함하지 않습니다.
